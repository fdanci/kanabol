# Frontend

Angular 22 single page application.

## Connecting to the backend

The frontend calls `/api` and `/hubs` on its own origin, in development and in production, so there is no CORS anywhere. `src/environments/environment.ts` holds only those two paths, and the same build runs everywhere.

- In development, `npm start` uses `proxy.conf.json` to send both to the API on http://localhost:5200, with WebSockets for `/hubs`. Start the API first: `backend/CLAUDE.md` says how.
- In Docker and production, `nginx.conf` and `nginx.prod.conf` do the same, sending them to the `api` service.
- nginx sends the security headers of `docs/SPEC.md` §13.2 from `nginx-app.conf`, at server level and with `always`: an `add_header` inside a `location` would drop them all there. `nginx.prod.conf` adds HSTS on 443 only. The CSP allows scripts from this origin only, so `index.html` holds no inline script: the production build doesn't inline critical CSS (`inlineCritical: false` in `angular.json`), whose stylesheet waits on `media="print"` for an inline script to switch it. Styles may be inline (`style-src 'unsafe-inline'`), as Angular and Material put them. `scripts/check-hardening.sh 1` checks all of it on the image.
- Feature code calls the API through `ApiClient` (`core/api`), in a `<feature>-api.ts`, never through `HttpClient` directly.

## How a request goes

- `correlationInterceptor` gives each API request an `X-Correlation-Id`. `errorInterceptor` shows a failed request in the error snackbar, with the end of that id, and passes the error on. It leaves a 401 to the session and a 400 with field errors to the form. A request that shows its own errors sets the `QUIET` context token, and one that shows only some codes itself, such as an email already taken under its field, passes `handledHere('User.EmailTaken')` as its context. The refusals of `docs/SPEC.md` §4.4 have Romanian messages in `BY_CODE`.
- `authInterceptor` sends the access token. On a 401 it waits for one refresh, shared with whatever failed at the same time, and sends the request once more. If the session is over, the user goes to the login page.
- `AuthStore` keeps the access token in memory only, never in storage. At startup it gets a new one from the refresh cookie, before the first page. Tabs take turns to refresh, through `navigator.locks`: two tabs sending the same cookie at once would look like a stolen token to the API and end the session. The cookie is the browser's, shared by every tab, so after someone else signs in elsewhere a refresh here answers for them: when its token's `sub` isn't the signed-in user, this tab ends its session instead of acting as them.
- `authGuard` opens a page to someone signed in, and only the password change page while `mustChangePassword` is on. `permissionGuard` is a `canMatch`: without the permission, the route after it on the same path matches and shows the 403 page at the address asked for. `withPermission` in `app.routes.ts` adds both.
- `connectionInterceptor` sends the tab's hub connection id in `X-Connection-Id`, from `TabConnection`, when it has one (below).
- `Logger` is the only code that writes to the console. `GlobalErrorHandler` logs what nobody caught. In production the Logger also hands warnings and errors to `ClientLogs`, which sends them to `POST /api/client-logs` for Seq: gathered for 5 seconds, at most 10 a minute, quietly, and only while signed in, since a 401 there would end on the login page.

## Real time

- `Realtime` (`core/realtime`) holds the one connection to `/hubs/board` (docs/SPEC.md §9), made by `HUB_LINK_FACTORY` with `@microsoft/signalr`, over WebSockets only, as the API offers, after a negotiation that gives the connection id. The bell opens it once the user is signed in (`open()`, no project: the API joins the user's own group by itself), a board joins its project on it, and it closes when the session ends. SignalR reconnects by itself, after 0, 2, 10 and 30 seconds, and when it gives up, or can't start, `Realtime` starts it again after 1, 5, then every 30 seconds; after either, it joins its projects again and calls the `onReconnected` handlers, who read what they missed. `JoinProject` answers null for a join and the code for a refusal, such as `Project.MemberRequired`, which goes to the log as a warning: the board says so itself when it reads.
- The token goes in the hub's address, so the connection asks `AuthStore.freshToken()` each time it connects: the token, or a refreshed one when it has 30 seconds or less left, counted from its own lifetime (`exp` less `iat`) since it came, as this computer's clock may be off the API's. The API closes a connection when its token expires, with leave to reconnect, which SignalR does with a fresh one.
- `on('TaskMoved', handler)` gives the payload typed by the event's name (`BoardEvents` in `core/realtime/models.ts`) and returns the function that stops listening. The board listens to its project's events and the bell to `NotificationCreated`; not the List, the panel or the notifications page.
- The connection's id lives in `TabConnection`, which `connectionInterceptor` reads, so the API's requests don't pull SignalR into the first bundle. The bell, which is in the first bundle, reaches `Realtime` only through `import('../realtime/realtime')`; the board's store imports it as usual, so SignalR comes in one chunk the two share.
- `HubLog` passes SignalR's log to `Logger`, with `access_token` hidden: warnings and errors as warnings, since a lost connection comes back by itself, critical ones as errors, the rest as debug.
- Specs stand in for the connection with a `HubLink`, and for the whole service with `FakeRealtime` (`realtime-testing.ts`), which any spec that shows the board or the bell provides, its `opened` counting the bell's `open()`: `provideFakeRealtime()`.

## UI

`docs/UI_UX_SPEC.md` decides how everything looks and behaves. Read the section for what you're building.

- Components only use `var(--kb-*)`, never hex values, in inline styles too. Material takes its colors from the theme in `src/styles.scss`.
- White text and checkmarks only go on `--kb-fill-accent` and `--kb-fill-danger`. `--kb-accent-600` and `--kb-danger-600` get lighter in dark, to read on the cards, and white text on them falls below AA there.
- No `::ng-deep`, and no rules on Material's own classes. Material is styled through the `mat.*-overrides` mixins in `src/styles.scss`, and our classes go on the host elements.
- Buttons: `matButton="filled"` with `kb-default` once per surface, or with `kb-danger` for destructive actions; `matButton="outlined"` with `kb-bezel`; plain `matButton` for text. No `elevated` or `tonal`. They're 32px; `kb-regular` brings one to 28px and `kb-sm` to 24px.
- Forms use `kb-field` on a plain `input` or `textarea`, in `kb-form-group` rows of `kb-form-row` with a `kb-form-label`, and `kb-field-error` under a field. `mat-form-field` is only for a one-field quick create.
- Menus take `class="kb-menu"`, and a destructive item `class="kb-menu-danger"`. Dialogs are sheets by default (`MAT_DIALOG_DEFAULT_OPTIONS` in `app.config.ts`), with a width from `SHEET_WIDTH`. `Confirmation.ask` asks before anything that can't be undone, and `Confirmation.discardChanges` before unsaved changes are lost. A sheet with a form calls `askBeforeClosing(ref, changed, confirmation)`, so Esc and a click beside it ask first.
- Tables are a `mat-table` with `kb-table`, inside a `kb-table-card`, with `kb-table-row` on each `mat-row` for the zebra and `kb-row-actions` on the ⋮ button, which shows on hover. A `mat-paginator` under it offers 25, 50 and 100, with the Romanian labels of `PaginatorLabels`, which the component that shows it provides itself: `providers: [providePaginatorLabels()]`. Provided in `app.config.ts`, the paginator, and the `mat-select` and forms it brings, went into the first bundle (`scripts/check-hardening.sh 5` refuses a paginator without it).
- A select in a form is a `mat-select` with `class="kb-field kb-select"` and `panelClass="kb-menu"`, labelled by `aria-labelledby`.
- Lists of the API come in a `Page<T>` (`shared/models/page.ts`). The password policy is in `shared/models/password-policy.ts`.
- Icons inside Material components are `<mat-icon>`, which draws with the self-hosted Material Symbols at the size its place gives it. Elsewhere a `span.material-symbols-outlined` with its own `font-size` is fine.
- Feedback on an action goes through `Snackbar` (`show`, and `error` with the correlation id). Lasting context goes in a `kb-banner`.
- Shared pieces live in `shared/ui`: `kb-banner`, `kb-chip`, `kb-empty-state`, `kb-skeleton`, `kb-upload-zone`, `kb-avatar`, `kb-avatar-stack` (the people of a task, overlapping, at most three and "+N", every name in its tooltip and `aria-label`), `kb-page-header`, `kb-lockup`, `kb-segmented-nav` for the views of one thing, as router links in the page header, `kb-stat-tile`, a number on the main panel or a text such as a duration in the reports, and `kb-chart`, the reports' bars. Pages start with a `kb-page-header`. `Section` (`shared/section.ts`) is a part of a page read on its own, with its own state, which the main panel and the reports share.
- A sheet's fields are `Field`s (`shared/ui/field.ts`): the value, the problem the form finds once the field was left or the form sent, and the one the API found, until the value changes.
- A filter toggle is a `button.kb-filter-chip` with `aria-pressed`.
- Times go through the `relativeTime` pipe, with `fullDate` in a tooltip (docs/UI_UX_SPEC.md §11): relative under 7 days, the date after that.
- An effect that starts a load wraps it in `untracked`, or the signals the load reads start it again, without end.
- Fonts and icons are self-hosted, because the app runs on the LAN. Nothing comes from Google Fonts or a CDN.
- The first bundle, what `index.html` loads, is 707 kB after group 22 (706 kB after group 19, from 893 kB), under its 750 kB budget, the error at 1 MB (`docs/SPEC.md` §6.2): the shell's own Material (sidenav, menu, buttons, tooltips, the snackbar and the overlay under them) and the dialog, whose defaults `MatDialog` reads from the root injector. Nothing else of Material goes in: `ThemeToggle`, the only slide toggle, sets its defaults itself and the navbar loads it with `@defer (on idle)` (`mat-menu` makes its content with the navbar, so it's there before anyone opens the menu), and the paginators' labels come with their pages. `npx ng build --stats-json` writes `dist/kanabol/browser-stats.json`, whose `outputs` say what each file holds; `scripts/check-hardening.sh 5` prints the Initial total.
- Text is in Romanian, in sentence case, and goes through `i18n`: the `i18n` attribute in templates, `$localize` in code. Dates and numbers format as `ro-RO`.
- Under `prefers-reduced-motion: reduce`, a rule at the end of `styles.scss` takes every transition to 0 ms, Material's and ours (docs/UI_UX_SPEC.md §8); `kb-skeleton` stops its shimmer itself, and the board neither slides nor pulses. Nothing may wait for a `transitionend`, which a transition of 0 ms never sends; Material skips its own animations under reduce.
- The sidebar's version is `APP_VERSION` (`core/layout/sidenav.ts`). The commit a version tags sets it, and the default tag of `compose.prod.yaml` with it (docs/SPEC.md §13.5); `scripts/check-docker.sh 3` fails when the two differ, and `scripts/release.sh` refuses a tag that isn't that version.
- Everything on a page is in a landmark: the navbar is the `banner`, the sidebar's links its `nav` and the version its `footer`, the page `main`. An `aria-label` goes only on an element with a role (`role="img"` on an icon that says something), and a field's `aria-describedby` names its error only while the error is on the page.
- `axe-core` is a dev dependency for the UI review, run by hand in a browser on every screen of docs/UI_UX_SPEC.md §7, in both themes; `docs/ui-review.md` has what it found and the screenshots are in `docs/screens/`. The app never imports it. `--kb-text-500` (#697078, #8692ae in dark) passes 4.5:1 at the `caption` size on every background it's on, and the dark `--kb-sky-300` (#3b6cc7) under `text-900` on the Owner chip, since group 20; `--kb-chart-2` keeps #3d6fc9 in dark. A change of tokens means axe-core again and the screenshots taken again, with the same data (`scripts/demo-data.sh`).

## Projects

- `/projects` lists what the API lets the user open, for anyone signed in. `/projects/:id` opens on `board`, next to `list`, `members`, `reports` and `settings`; the board, the list and the reports are other features' pages, which `projects.routes.ts` loads. On the board the page drops its width limit, since the board is full-bleed.
- `ProjectPage` provides one `ProjectStore` for its views, so they share the project and another project starts from nothing. `canManage` from the API (an owner, or `projects.manage`) shows Setări and the changes, and an archived project changes nothing until it's restored.
- The member sheet looks for users through `GET /api/projects/{id}/member-candidates`, so an owner without `users.manage` can still add someone.
- The last active owner's row has no ⋮, nor has a deactivated owner's while no owner is active: the API refuses to remove or demote them anyway (409 `Project.LastOwner`). `ProjectStore.keepsAnActiveOwnerWithout` decides it.

## Tasks

- A task opens in its panel, over the page it was opened from, through a router outlet of its own next to the page: `/projects/p1/list(panel:task/KAN-12)`. Any feature opens and closes it with `openTaskPanel` and `closeTaskPanel` (`shared/task-panel.ts`), which keep the page's query, so features don't import the tasks feature. `/tasks/KAN-12`, the address a task is shared by, finds its project and opens it over the project's board.
- `TaskPanelRoute` is what the outlet shows: it opens `TaskPanel` as a `MatDialog` with `taskPanelConfig` (920px, from the right, the window's height less 12px each side), and the outlet closes with the panel. Leaving the address, the back button for one, closes the panel.
- `TaskPanelStore` reads the task by its key, with `includeArchived` for `tasks.archive`, then the project's columns and members when the caller can change it (`canChange` from the API). Every change answers with the task as saved; a 409 reads it again, a refused field comes back by name and the panel says it in Romanian (`task-fields.ts`). `TaskChanges.version` counts the changes, so a list behind the panel reads its page again.
- A task has any number of assignees (docs/SPEC.md §4.4). The panel and the "Task nou" sheet pick them from a `mat-select` with `multiple`, its options and its `mat-select-trigger` showing avatars and names, "Neasignat" as the placeholder for nobody, the select growing a row when the names don't fit. The panel sends the whole list to `PUT /api/tasks/{id}/assignees` saved once, when the list closes, nothing when it closes as it was, and puts the ticks back when the API refuses. A deactivated assignee can be taken off, but not ticked again. `MatSelectHarness.close` clicks the first backdrop of the page, which in a sheet or the panel is the dialog's, so the specs close a list with Esc on its trigger. `assigneesChange` (`task-history.ts`) writes an `Assignees` history entry with names, «Ana → Ana, Dan».
- In the panel the priority select shows its `kb-chip` through a `mat-select-trigger`, as the options do: without one, mat-select shows the option's text, the icon's ligature included, "arrow_upwardHigh". `chosenPriority` holds the chip shown, the one chosen at once, then the task's as saved or as it was after a refusal.
- The panel's tabs are a `mat-tab-group`, the only one in the app (UI spec §6.7): 36px, 13px/500 labels, a 2px `accent-600` indicator, through `mat.tabs-overrides` in `styles.scss`. "Comentarii" is `kb-task-comments`, "Atașamente" `kb-task-attachments` and "Istoric" `kb-task-timeline`.
- From group 22 (UI spec §7.5) the panel has, after Deadline, "Estimare", edited in place as the title is (Enter and leaving the field save, Esc goes back, an empty field takes it away; hours with a comma or a dot, `PUT /api/tasks/{id}/estimate`), and "Timp lucrat", read only, with `play_circle` and its tooltip while the task counts in În lucru and "din 4 h estimate" under it, danger-600 once past. In În pauză "Motivul pauzei" shows under "Stare". The "Stare" select asks the board's sheets (`MoveQuestions`) for În lucru without an estimate and for every pause, goes back without a request when one is turned down, and has the columns before În lucru off for a started task. Atașamente and Istoric have a `kb-refresh-button` (`shared/ui`) on the right of their first row, 28px, which reads the task again (`TaskPanelStore.refresh`) or the history (`TaskTimelineStore.reading`), turning while it reads. The timeline writes «a estimat task-ul la 4 h», «a schimbat _Estimarea_: 4 h → 6 h» and «a pus task-ul pe pauză: «…»».
- `kb-task-comments` reads the task's comments through its own `TaskCommentsStore` (`CommentsApi`), from the oldest, and again when the panel shows another task. Each is an avatar, a name, a relative time with the full date in its tooltip, "editat" once edited, and its text through `kb-markdown`. "Editează" turns the caller's own into a field in place, when the API says `canEdit` and the caller can comment. Whoever can change the task has a form at the end, sent by its button or Ctrl+Enter; it keeps its text until the API takes it, and refuses more than 5,000 characters itself. A new comment counts on the board's card, so it tells `TaskChanges`.
- `kb-task-attachments` lists the task's files from its DTO, each downloaded under its name: the token is in memory, so `AttachmentsApi.download` reads the file as a blob and a link the page clicks saves it. Whoever can change the task gets `kb-upload-zone`; each file chosen goes up in a request of its own, as multipart in the field `file`, with a row and its progress until the API has it, then `TaskPanelStore.attached` puts it at the end of the list and tells `TaskChanges`. A file over 25 MB is refused in its row without being sent, one the API refuses says so in its row, and taking a row away stops its upload. A file whose `canDelete` the API gives is deleted after `Confirmation` asks.
- `kb-task-timeline` is the "Istoric" tab (UI spec §7.5): `GET /api/tasks/{id}/history` through `TasksApi.history`, held by its own `TaskTimelineStore`, from the newest, 50 at a time, with "Încarcă mai multe" at the end while there are more, a change already shown kept once. The tab's content is a `matTabContent` template, so the timeline is made, and reads, each time the tab opens; `TaskPanelStore.savedChanges` counts the changes the panel saved, and each one reads the history again, keeping what it shows until the answer comes. Nothing comes from SignalR. `historyLine` (`task-history.ts`) writes each entry: «**Florin** a schimbat _Prioritate_: Medium → High», the priority by its label, a deadline as its day in ro-RO or "fără deadline", a column by the name the API gives or "coloană ștearsă", the assignees through `assigneesChange` with the entry's `names`, the description without its texts, "a arhivat task-ul" and "l-a restaurat". Angular drops the spaces between elements, so the line keeps them with `&ngsp;`.
- A change of the description offers "Vezi diferența" (UI spec §7.5): the list sends that entry without its texts, so `TaskTimelineStore.toggleDiff` reads it once through `TasksApi.historyEntry` (`GET /api/tasks/{id}/history/{entryId}`, whose `History.NotFound` the block says itself) and keeps it, open or closed, while the timeline shows the same task. Under the row, a block of at most 240px, padding and border included, shows a two-row skeleton, "Nu am putut încărca diferența." with "Reîncearcă", or `kb-description-diff`, and "Ascunde" closes it. `descriptionDiff` compares the markdown source word by word with `diffWordsWithSpace` from the `diff` package (jsdiff), whitespace kept, so the source's lines stay: deletions struck through on `danger-bg`, insertions on `success-bg`, the rest as it is, and nothing rendered as markdown or HTML. A comparison that would take over 500 ms gives the old text deleted whole and the new one added whole.
- `diff` is imported only by `description-diff.ts`, so it comes in the panel's chunk (`task-panel-route`), never in the initial bundle. The timeline doesn't use `@let` either: its runtime would go to the shared initial chunk, about 0.25 kB.
- `HttpClient` runs on XHR (`withXhr()` in `app.config.ts`): Angular 22's default, fetch, can't report how far an upload went. `ApiClient.upload` sends a form with `reportUploadProgress`, and `ApiClient.blob` reads a file.
- A deadline is a day: the panel stores the end of that day where the person is (`endOfDay`), so a task due today isn't late until midnight. `kb-deadline-chip` (`shared/ui`) colors it as UI spec §6.5 says, neutral once the task is done.
- Markdown goes through `kb-markdown` (`shared/ui/markdown.ts`), which renders the tree `parseMarkdown` reads through templates. Nothing in the app sets `innerHTML` or bypasses the sanitizer: raw HTML is dropped, links go only to http, https and mailto, with `rel="noopener noreferrer"` (docs/SPEC.md §16). `scripts/check-tasks.sh 7` fails on any of it.
- The List view (`TaskListPage`) keeps its filters, sort and page in the address, so a list can be shared and the back button goes through them. The filters are the board's (docs/UI_UX_SPEC.md §7.4), in `shared/` for group 13: `TaskFilters` and their query (`shared/models/task-filters.ts`), and `kb-task-filter-bar` (`shared/ui`). "Ale mele" is `assignee=me`, the tasks of whoever opens the link. A task passes the assignee filter when that person is among its assignees, and its row shows them all in a `kb-avatar-stack`, or "Neasignat". A row opens the panel and keeps the query.
- The headers sort through buttons of their own with a 12px chevron (UI spec §6.4), not `MatSort`, whose arrow Material draws.
- The table is `kb-task-table` (`task-table.ts`), which the List and "Task-urile mele" share: the columns a page asks for, the headers' sort buttons, rows that open the task, and the paginator; the page keeps the address and decides the sort's direction.
- `/my-tasks` is `MyTasksPage` (UI spec §7.2): `GET /api/me/tasks` through `TasksApi.myTasks`, held by its own `MyTasksStore`, the List's table with a "Proiect" column, 50 to a page, by deadline from the soonest (`MY_TASKS_SORT`, which the address leaves out, as `sortToQuery` and `sortFromQuery` take a page's own default). `kb-task-filter-bar` there has `withAssignee` false, without "Ale mele" and the select, and `finished`, the chip "Și cele terminate" (`done=1`), off by default, so the API gets `open=true`; it adds tasks, as "Și cele arhivate" does, so "Șterge filtrele" keeps both. "Niciun task deschis." without filters, "Niciun task pentru filtrele alese." with them, "Nu am putut încărca task-urile." with "Reîncearcă". The main panel's "Întârziate" tile leads to `/my-tasks?overdue=1`.
- `mat-select` takes an option whose value is `null` for no choice at all and shows nothing, so "Neasignat" and "Oricine" have the value `''`.

## Board

- `board-store.spec.ts` holds the store's moves and rollbacks against a fake API whose answers the specs hold and let go, and `board-moves.spec.ts` the pure `moveCard` and `placeAmong`; `board-page.spec.ts` drives the page, drops included, through the column's `dropped` output, with the fixtures in `board-testing.ts`.
- `BoardPage` (`features/board`) reads `GET /api/projects/{id}/board`: the columns and every open task, without pages, since the board shows them all. `BoardStore` holds it as a `resource()` of the project's id, with the members as another, and keeps the old board while it reads it again, so the cards don't blink.
- Cards move with CDK drag and drop: `cdkDropListGroup` on the board, a `cdkDropList` per column (`BoardColumn`), `cdkDrag` on each `TaskCard`. A drop moves the card at once (`moveCard` in `board-moves.ts`, which numbers the columns 0, 1, 2... as the API does), then sends `PATCH /api/tasks/{id}/position`; when the API refuses, the card goes back to its place and the board is read again. `errorInterceptor` has shown why by then.
- The CDK gives the place among the cards a column shows; `placeAmong` turns it into the place among all its cards, which the filters may hide some of.
- The card's look is on an inner `.card`, because the CDK moves the dragged copy with a `transform` on the host: the tilt of a picked-up card (UI spec §6.0.10) goes on the inner box, as do the placeholder's outline and the 200ms reordering.
- Dragging and "+ Task" follow `canMove` from the API, a real member of an open project, and "+ Task" also `tasks.create`. "+ Task" opens a title field in the column; Enter creates the task at its end, with the default priority, and the field stays for the next one.
- From the keyboard (UI spec §7.4): Space on a focused card picks it up, the arrows move it to another column, keeping its row as far as that column goes, or up and down, Space lets it go and Esc puts it back. Only letting go asks the API. `LiveAnnouncer` says each step in Romanian, every card is described by the keys' help, and the focus follows the card as it is drawn in its new column (`afterNextRender`).
- The filters are the List view's (`kb-task-filter-bar`, `TaskFilters`) and live in the address the same way, without the archived ones. They work in the browser on the cards the board has (`cardFilter` in `board-filters.ts`), a card passing the assignee filter when that person is among its assignees; a column counts the cards it shows. A card shows its assignees in a `kb-avatar-stack`, or an empty dashed avatar for nobody. A card dropped or let go among filtered cards lands just before the card it went above, or just after the last one shown, so the hidden ones keep their places.
- Every project has the fixed columns Backlog, În lucru, În pauză and Gata (docs/SPEC.md §4.4, by `kind`), each with a 3px bar on its top edge, an inset `box-shadow` that follows the corners, and a 16px icon before its name, decor (`aria-hidden`), both in its kind's existing token (`--kb-kind`: text-500, accent-600, warning-600, success-600), over 3:1 on the column in both themes; the project's own columns (`Custom`) have neither. "+ Task" is only in Backlog, where every task starts. - A move into În lucru of a task without an estimate, and every move into În pauză, asks first (UI spec §7.4), by the mouse and the keyboard: `MoveQuestions` (`shared/`, as the task's panel asks the same) opens the 440px `EstimateSheet` or `PauseSheet` (`shared/ui`) and answers the minutes or the reason, or null. `BoardStore.moveTask` takes that question: the card waits in its new place, the board keeping still, then goes back without a request when it's turned down, or shows what the answer gave it and sends it with the move. Hours are read with a comma or a dot and stepped by 0.25 with the arrows (`shared/models/estimate.ts`, which also writes durations in hours and minutes, never days).
- With an estimate, the card's third row has a `kb-chip` with `timer` and "lucrat / estimat", as of the board's last read, the `over` kind (danger) past the estimate and the icon in accent-600 in În lucru; in În pauză a row under the title has the reason on one line, whole in its `matTooltip` and in the card's accessible name.
- Arhivate (UI spec §7.4) is `kb-archived-column`, last, after "+ Coloană", for `canSeeArchived` (`tasks.archive` in the token). It isn't a row of `board_columns`: its drop list's data is `ARCHIVED_COLUMN`, and `ArchivedStore`, provided with `BoardStore`, reads `GET …/board/archived` 50 at a time, again after an archiving or a restoring, this tab's or anyone's (`TaskArchived`, `TaskRestored`). Closed it's a 44px band with `inventory_2`, its name written downwards (`writing-mode`) and its count, a button that opens it at 300px; the state stays in `localStorage` (`kb.board.archived`, every access in `try`). Its cards are `kb-task-card` with `archivedAt`: 0.72 opacity, "arhivat acum 3 zile" in place of the deadline. A card of the board let go on it is archived after `Confirmation.ask`, one of its cards let go anywhere on the board goes back to its own column («KAN-12» a revenit în «În lucru».), so every column's enter predicate takes an archived card; from the keyboard each card has a ⋮ with "Restaurează". - For `canManage` (an owner or `projects.manage`, open project) each column of the project's own has a ⋮ (`kb-menu`), the fixed ones none: "Redenumește" turns the name into a field in place (Enter and leaving it save, Esc gives up), "Mută la stânga" and "Mută la dreapta" as far as Backlog and Gata let it, and "Șterge" only for an empty one, after `Confirmation.ask`. A column with only archived tasks gets 409 `Column.NotEmpty`, which `BY_CODE` says in Romanian. "+ Coloană" after Gata opens a name field, and the new column comes right before Gata. The ⋮ is 28px with a 16px icon, from `mat.icon-button-overrides` on `kb-board-column` in `styles.scss`.
- A card opens its panel with `openTaskPanel`, keeping the query, and `TaskChanges` (`shared/`, so the board needn't import the tasks feature) makes the board read itself again after the panel saves.
- What others change comes through `Realtime` (docs/SPEC.md §9, UI spec §7.4). `BoardStore` joins its project when it opens it and leaves it when the page goes, and ignores what comes for another project, and what its own user did from this tab: the event's `originConnectionId` is this tab's and its `byUserId` the signed-in user, since anyone on the project sees the tab's id and could send it in `X-Connection-Id`. `TaskMoved` moves the card in place, and `BoardPage` slides it there in 200ms: a copy of its box, fixed to the window so no column clips it, goes from the old place to the new while the card waits under it. `TaskCreated`, `TaskUpdated` (`Attachments` among its fields, for a file attached or taken off), `TaskArchived`, `TaskRestored` and `CommentAdded` make the board read itself again quietly, as does a reconnection: the counts on the cards come with the board. Every card someone else changed pulses once with `--kb-tint-100` in 600ms, through `pulses` in the store and the card's `pulse-a` and `pulse-b` classes, two names so the next change starts it again. Under `prefers-reduced-motion` neither moves.
- While a card is in hand, dragged (`dragStarted` and `dragEnded` of the column) or picked up from the keyboard, while a move of this tab's waits for the API, or while the first read is on its way, `BoardStore.hold`, `moving` and the read's state make what others do wait; the board then reads itself once, so nothing moves under the cursor and no read from before a move puts a card back.

What it marks read it tells `BellStore.readAgain()`.
- A component's inline `styles` are CSS, not SCSS: a `//` comment there breaks the rule after it, and the build only warns. `scripts/check-alerts.sh 3` fails on any build warning but the budget's.

## Reports

- `/reports` is `ReportsPage` (`features/reports`, docs/UI_UX_SPEC.md §7.8), for `reports.view`: the h1 "Rapoarte" under Acasă, the filters' card, then "Task-uri finalizate", "Lead time și cycle time" and "Deadline-uri", each a `Section` of `ReportsStore`, read on its own from `GET /api/reports/completed`, `cycle-time` and `deadlines` through `ReportsApi`, with its `kb-stat-tile`s, its chart, the table of its data with "Export CSV", a skeleton, its empty text ("Niciun task finalizat în interval.", "Niciun task cu deadline în interval.") and "Nu am putut încărca raportul." with "Reîncearcă" for it only.
- From group 22 a fourth section, "Estimare și timp lucrat", reads `GET /api/reports/work-time` (`ReportsStore.workTime`): the tiles Estimat, Lucrat, Abatere ("+18 %", "−5 %" with a true minus, "—" without data) and Peste estimare; estimated and worked by person in the charts' two colors, in hours; the tables "Pe om" and "Pe proiect" with their deviation, exported together as `kanabol-estimare-…`; "Task-uri peste estimare", at most 20, each opening its task's panel (`openTaskPanel`). Under its title, the work schedule of now, which `ReportsApi.workSchedule` reads once (`GET /api/settings/work-schedule`, anyone signed in), its days as a range or one by one. "Niciun task finalizat cu estimare în acest interval." without an estimated task.
- Every filter is in the address (`report-filters.ts`): `from` and `to` as days where the person is, both included, `project`, `user` and `granularity=month`; the last 30 days, today included, by the week, are the default and stay out of the address. A wrong interval in the address (one end missing, a day that isn't one, `to` before `from`, over 366 days) goes back to the last 30 days, replacing the address. The chips "Săptămâna asta" (Monday to Sunday), "Luna asta" and "Ultimele 30 de zile" write their days, pressed when the interval is theirs; the two `mat-datepicker`s are bounded by each other and by 366 days (`earliestFrom`, `latestTo`). Another project takes the person chosen away.
- The API gets midnight of `from` and midnight after `to`, where the person is, with the offset each has that day (`localInstant`): `ReportsApi` encodes every character itself, since Angular's own codec leaves a `+`, which the API reads as a space. The periods come back on the person's clock, so a period is named by the day in its `periodStart`, not by converting the instant.
- The project select reads `GET /api/projects?includeArchived=true&pageSize=100`, the archived ones said so; the user select offers the members of the project chosen, read quietly, or, without a project or without leave to read its members, everyone a report of the finished tasks has named so far.
- Durations show as "2 z 4 h", "5 h 20 min" or "35 min", rounded to the minute, "–" for nothing (`formatDuration`); the rate as a percent, "–" when null. The times' chart is in hours on its axis, with the full duration in its tooltip: with a project, each of its columns; without one, lead and cycle time side by side.
- "Export CSV" is made in the browser (`report-csv.ts`): a BOM, every field in quotes, commas, CRLF, saved through a link the page clicks as `kanabol-finalizate-…`, `kanabol-durate-…` (seconds) or `kanabol-deadline-uri-…` with the interval's days.
- The project's "Rapoarte" tab (docs/UI_UX_SPEC.md §7.3), for an owner, `projects.manage` or `reports.view`, is the same page: `projects.routes.ts` loads `ReportsPage` with `projectFixed` in its data, the one feature another's route loads (docs/SPEC.md §6.1), and the page stays in its own chunk. There the project is the route's `id`, whatever the address says, and stays out of it; no title, breadcrumb or project select, and the project page gives the width; the user select offers its members, and no list of projects is read. An owner without `reports.view` reads the reports of that project only, which the API checks.
- `kb-chart` (`shared/ui/chart.ts`) draws bars on a canvas with chart.js 4, registering only the bar's pieces: the main series `--kb-chart-1`, the second `--kb-chart-2`, over 3:1 on the card in both themes (docs/UI_UX_SPEC.md §2.1–§2.3; brand-800 had 1.4:1 on the dark card and sky-300 1.8:1 on white), the grid `--kb-border-200`, a 2px gap in the card's color between stacked pieces, a 4px rounded end, a legend only for two series or more, and its colors read again when the theme changes. Its tooltip is an element of its own, written as text, with the global class `kb-chart-tooltip` in `_utilities.scss` for its white on ink. `CHART_RENDERER` draws; specs give a fake, since jsdom has no canvas.
- The page shows each chart inside `@defer (on idle)`, so `kb-chart` and chart.js come in a chunk of their own after the page, and `ChartSeries` is an `import type`: a symbol of the chart named outside `@defer` keeps it in the page's chunk. The first `@defer` brought Angular's runtime for it into the initial bundle, about 9 kB; the navbar's theme switch uses it too, so `kb-chart` keeps `@defer` rather than an `import()` of chart.js, which would save nothing.

## Access rules

- Hiding something in the UI is not access control: the backend enforces permissions.
- Show or hide based on permissions, never role names: `*kbHasPermission="'users.manage'"`, with the names in `PERMISSIONS` (`core/auth/permissions.ts`).
